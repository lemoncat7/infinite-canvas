# 后端职责边界

本次把原约 5,862 行的 `api/src/server.ts` 拆为领域模块；不是将整份文件挪到另一个大文件中。

| 位置 | 职责 |
| --- | --- |
| `server.ts` | 监听端口、启动工作队列、响应退出信号 |
| `application.ts` | 组合路由、恢复启动状态、关闭资源 |
| `http/` | Fastify 实例、健康检查与诊断入口 |
| `storage/` | SQLite 初始化、迁移、查询与原子文件替换持久化 |
| `auth/` | 身份认证、Token、会话、Cookie、登录与设备接口 |
| `projects/` | 项目 CRUD、所有权检查、默认项目 |
| `canvas/` | 画布读取、版本/记录级同步、历史压缩、重置与旧接口 |
| `generation/` | 提交验证、请求去重、执行队列、生成状态、模型运行配置 |
| `billing/` | 点数兑换及生成任务点数结算 |
| `assets/` | 资产接口、缩略图、生成输入签名、生成结果归档、视频导出 |
| `comic/` | 对话/会话入口与独立的剧情资产、分镜、连续性审校、结果整理阶段 |
| `agents/`、`speech/` | 提示词助手与语音入口 |
| `notifications/` | 通知、在线状态、反馈与管理接口 |
| `models/`、`providers/` | 原有模型配置及供应商适配，不复制已有实现 |
| `mcp/` | MCP 协议、工具 schema、工具编排及 API 适配 |
| `core/` | 小型共享类型、错误、JSON、日志及启动恢复逻辑 |

## 依赖方向

MCP 工具通过 **进程内 API gateway** 调用现有已认证的 HTTP handlers。它使用 Fastify `inject`，不访问公网、不另起 HTTP 连接、不允许 Agent 自选接口路径，也不直接读写数据库。这样网页与 MCP 共用所有权验证、画布版本冲突、模型选择、生成校验和点数逻辑。

生成提交已提取到 `generation/submit.ts`；队列、去重存储、点数结算、资产归档各自独立。其余领域的 HTTP handlers 暂时保留已有业务处理行为，避免为了抽象而重写所有策略；后续若出现第二个调用方，可按领域继续提取应用服务。不要用一个包含所有服务的无类型 context 或工具层 SQL 取代这些边界。

核心服务不反向导入 HTTP 实例；日志由应用组合层注入。MCP 不 import `storage`、`models/store` 或供应商 adapter。

## 稳定性约束

- 保留原 HTTP 路径与鉴权方式；旧画布兼容入口仍在。
- 保留画布批次缓存与记录级冲突检测；MCP 不用整张画布覆盖来更新节点。
- 新增的 `generation_requests` 是加法迁移，以 `(user_id, request_key)` 唯一约束保存去重记录。预留点数、任务、去重键在同一 SQLite 事务中写入。
- 退出时停止新任务和探活定时器，等待正在执行的生成任务结束后再关闭数据库；进程被强制终止仍走原有启动恢复逻辑。
- `noUnusedLocals`、`noUnusedParameters` 纳入 API 编译，防止拆分后残留死代码。
- `test:architecture` 守住入口规模、依赖边界和原 HTTP 路由清单；`test:mcp` 用官方客户端验证认证、隔离、画布冲突、生成幂等及跨进程重试。
- 数据库仍是单进程 SQL.js 文件持久化，不支持多个 API 实例同时写同一数据目录。本次没有承诺多进程分布式锁。

## 不做的事

本次不改前端样式、不迁移用户数据目录、不重新定义生成/计费策略、不部署或发布。部署前需在目标环境完成构建和健康检查；应同时备份 SQLite 文件、资产及模型加密密钥。
