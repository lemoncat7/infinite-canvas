# 画布同步与数据安全

## 当前协议

每个项目画布由服务器维护单调递增的整数 `version`。

1. 客户端登录或进入项目后先关闭自动保存。
2. 客户端读取完整画布，校验版本、节点 ID 唯一性和连线端点完整性。
3. 只有完整恢复成功后才开启自动保存。
4. 客户端以服务器快照为基线，只提交节点、连线和相机的记录级操作批次。
5. 服务端为每个批次分配连续版本，并以 `batchId` 保证重试幂等；同一批次在服务重启后重复提交也不会重复应用。
6. 不同记录的并发修改自动合并；同一记录冲突、清空前旧基线和悬空连线全部拒绝，事务失败时画布与版本均不变化。
7. 旧式整份文档保存仍禁止把非空画布直接覆盖为空；记录级同步允许经过版本与冲突校验的明确删除操作删掉最后一个节点。
8. “清除画布”仍使用独立接口，校验下一版本并在清空前强制创建快照；它与逐个删除节点语义不同。
9. 退出登录先停止定时保存、排队保存并中止正在执行的保存请求，再清除登录状态。
10. SQLite 导出先写临时文件，再通过原子重命名替换正式数据库文件。
11. 每台设备加载项目时从服务端租用独立节点 ID 号段；号段不可用时禁止创建节点，避免多设备同时新增发生 ID 碰撞。
12. 删除操作保留 tombstone，阻止旧设备从过期基线复活已删除节点。

## 成熟项目的处理方式

### Excalidraw

Excalidraw 在元素级维护 `version` 与 `versionNonce`。远端元素版本较旧时保留本地元素；版本相同则通过 nonce 确定性裁决，并保护正在编辑、缩放或新建的本地元素。合并后还会修正元素顺序和重复索引。

参考：<https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/data/reconcile.ts>

### tldraw

tldraw 使用服务器 `documentClock`、每条记录的 `lastChangedClock` 和删除 tombstone。事务写入会同时推进时钟；事务失败时记录、墓碑、Schema 和时钟一起回滚。重连后按时钟获取增量，过旧时钟则强制获取完整快照。

参考：

- <https://github.com/tldraw/tldraw/blob/main/packages/sync/DOCS.md>
- <https://github.com/tldraw/tldraw/tree/main/packages/sync-core>

### Yjs

Yjs 使用 CRDT 与 state vector。更新具备幂等性和可交换性，可以乱序或重复应用；客户端交换状态向量后只同步差异，适合离线编辑和真正的多人同时编辑。

参考：<https://github.com/yjs/yjs#document-updates>

## 已实现的记录级同步

当前协议已经包含：

- 节点、连线与相机的记录级增量；
- 删除墓碑；
- 操作批次日志与幂等 `batchId`；
- 对不相交记录自动合并，对同一记录拒绝冲突；
- 版本推进、画布写入、墓碑和批次响应同事务提交；
- 服务端节点 ID 号段租约。

后续仍需加入操作日志快照压缩和安全清理。当前不启用离线写入队列；断线或记录冲突时以服务器快照为准，避免旧设备覆盖新内容。
