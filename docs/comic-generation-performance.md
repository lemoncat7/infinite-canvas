# 漫剧生成性能优化记录

## 当前基线

- 复杂测试：68 镜，总耗时约 43 分 54 秒。
- 镜头规划：约 3 分 54 秒，返回约 29 KB。
- 镜头扩写：每批 6 镜约 2–3.5 分钟，共约 12 批。
- 本轮只有最终审校对镜头 20 做了一次有效定向修复；主要耗时来自模型输出，不是重试。
- 准确性基线：场景 ID 复用、角色姿态/站位/朝向/持物状态、跨段审校均开启。

## 已完成但尚待实测

- 规划阶段不再让模型重复输出可由程序推导的 `entryState`、`motionLevel`、`frameCount`。
- 下一镜 `entryState` 由程序直接继承上一镜 `exitState`。
- 标题、运动等级和帧数由程序确定。
- `characterStates` 使用六项数组进行模型传输，服务端立即还原为可读对象。
- 状态未变化时要求 `transitionAction` 为空，减少重复静态描述。

目标：规划输出减少 30%–40%，角色状态传输减少 35%–50%。必须通过下一轮同等复杂度生成验证实际收益。

## 后续优化优先级

### P1：边界状态契约

在规划阶段为每镜固定：

```text
entryState -> coreAction -> exitState
```

每批扩写只接收当前规划、场景/资产索引和上一镜末帧状态，不携带不必要的完整镜头文本。批次输出必须按契约校验，失败只重写边界镜头。

验收：跨批姿态、站位、朝向、持物无跳变；输入体积和首字节时间下降。

### P2：Prompt Builder 消除重复输出

由程序动态补充固定内容：

- 风格、画幅与尺寸
- 禁止字幕、水印、额外人物等限制
- 场景基准描述与视觉锚点
- 角色 Visual Anchors
- 参考图编号和连线说明

AI 只生成剧情差异、构图、动作和必要对白。原始卡片描述不包含动态附加内容。

验收：最终生图/视频提示词信息不减少、无重复追加，镜头扩写输出体积明显下降。

### P3：两路受控并发

仅在 P1 的边界契约稳定后启用：

- 最多同时生成两个镜头批次。
- 批次可以并行返回，但必须按镜头编号顺序校验、保存和展示进度。
- 跨批边界使用固定契约校验；失败只修前一批末镜或后一批首镜。
- 不允许多个并发任务同时改写同一批次或检查点。

预期：镜头扩写耗时接近降低 35%–45%。

风险：未经边界契约直接并发会导致相邻镜头状态竞争、进度乱跳和恢复检查点不一致。

### P4：减少批次调用开销

实测 6、8 镜批次的首字节时间、总耗时、超时率和 JSON 完整率。只有 8 镜不会显著提高截断或重写率时才调整默认批次。

### P5：分层审校

- 程序负责字段、ID、数量、长度、姿态、站位、朝向和持物状态。
- AI 只负责剧情因果、语义连续性和程序无法判断的导演问题。
- 最终审校只检查批次边界及高风险状态变化窗口。
- 修复必须带错误码并只改对应字段或镜头。

### P6：缓存与恢复

- 为规划、资产、场景、镜头批次记录输入 Hash、版本和依赖。
- 未变化的阶段直接复用。
- 定向修改只使受影响镜头及下游生成失效。
- 刷新或重连继续使用同一 session 和已完成批次，不重复请求。

## 性能验收标准

以 60–70 镜复杂项目为标准：

- 第一目标：总耗时不超过 18 分钟。
- 理想目标：总耗时 12–15 分钟。
- 镜头规划不超过 2 分钟。
- 单批 6 镜平均不超过 90 秒。
- JSON 格式重试率低于 3%。
- 定向重写不影响已通过镜头。
- 刷新恢复后进度、输入禁用和生成按钮状态一致。
- 不降低人物、场景、道具复用与相邻镜头连续性。

## 实施原则

稳定性和准确性优先。每项优化必须先保留可回退提交，再用同一复杂方案对比耗时、输出字节、重写次数与最终连续性；未达到验收标准或出现状态串线时不得继续扩大并发。
